# EV Charging Station Anomaly Detection

Unsupervised anomaly detection for EV charging session telemetry.  
Detects physics violations, sensor faults, and subtle multivariate anomalies using a **Two-Gate Hybrid Architecture** (physics rules + Isolation Forest).

## Running the Project

All commands should be run from the **project root** directory.

### Step 1 — (Optional) Calibrate the contamination parameter

`find_contamination.py` is a **business calibration tool**, not a training dependency. It uses the Elbow Method on sorted Isolation Forest anomaly scores to suggest what fraction of data to treat as anomalies, and saves an annotated plot for visual inspection.

```bash
python find_contamination.py
```

Output: `data/anomaly_scores_elbow.png`

**Why `contamination=0.01` is already set and validated:**

The hardware fault rate (`error_code != 0`) is ~0.6% of rows — a natural lower bound. Running `find_contamination.py` on this dataset produces:

| | 2nd Derivative | Kneedle | **Current** |
|---|---|---|---|
| Contamination | 0.14% | 3.25% | **1.00%** |
| Rows flagged | 250 | 5,924 | **1,824** |
| Interpretation | Only undeniable outliers | Full anomaly population boundary | Middle ground |

**1% sits mathematically between both elbows** — right where the score curve transitions from steep anomalies to flat normal data. The right choice depends on the operational context:

- **Safety-critical (fire/thermal risk)** → use Kneedle's 3.25% — catch more, accept more false positives
- **Targeted maintenance** → use 2nd derivative's 0.14% — act only on the clearest faults
- **Balanced NOC operations** → current 1.0% is the engineering middle ground

Re-run this script only if retraining on a different dataset or changing the operational threshold.

### Step 4 — Evaluate confidence

```bash
python evaluate_model.py
```

Requires `data/predictions.csv` to exist (produced by Step 3).

This runs five independent evaluation checks:
- **A.** Gate overlap (independent agreement between rules and ML)
- **B.** Physics validation of ML-only anomalies (`power_mismatch` elevation)
- **C.** Hardware fault recall analysis
- **D.** Per-station anomaly distribution health
- **E.** Weighted composite confidence score (0–100)

Output: console report + `data/model_confidence_report.png`

## How It Works

### Two-Gate Architecture

Every row passes through two independent gates:

```
Gate 1 — Rules Engine          Gate 2 — ML Engine
(physics thresholds)           (Isolation Forest)

voltage < 150 V                 ┐
voltage > 280 V                 │  Imputer → Scaler
temperature > 70 °C             ├→ IsolationForest
current < 0                     │  decision_function
energy_kwh < 0                  ┘
        │                              │
        └──────────── OR ──────────────┘
                       │
                  is_anomaly (0/1)
```

A row is flagged as an anomaly if **either** gate raises a flag.

- **Gate 1** catches absolute physical impossibilities that are too rare for the ML model to reliably learn.
- **Gate 2** catches subtle, multivariate deviations across the full 10-feature space.

### Feature Engineering Pipeline

`run_pipeline()` in `src/data_processing.py` executes 9 stages:

1. Load CSV, parse timestamps
2. Deduplicate simultaneous sensor dumps (mean of numeric columns)
3. Compute `power_mismatch = |power_kw − (V × I) / 1000|`
4. Compute rolling means of voltage and temperature per session (window=5)
5. Extract `hour`, `day_of_week`, `hour_sin`, `hour_cos`
6. Apply frozen per-station temperature baselines
7. Compute `voltage_deviation` and `temp_deviation` (reading minus rolling mean)
8. Compute `session_energy_total` (cumulative energy per session)
9. Derive binary `is_error` flag from `error_code`

## Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| Unsupervised (not supervised) | `error_code` captures firmware faults, not physics anomalies. Training a classifier would only replicate what hardware already reports. |
| Isolation Forest over One-Class SVM | Scales to 182k rows; O(n log n) vs O(n²) kernel computation |
| Deviation features over raw readings | Decomposing voltage into level + spike gives the model two orthogonal axes per sensor |
| Frozen station baselines at inference | Prevents distribution-shift bug where a small inference batch computes very different per-station means than the scaler was fitted on |
| `error_code` excluded from Rules Engine | Prevents circular evaluation — keeping rules purely physics-based makes the confidence report non-trivial |
